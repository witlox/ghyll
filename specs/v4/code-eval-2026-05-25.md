# Code integrator pass — 2026-05-25

## Summary

The user's claim ("feature-complete except for the 4 GH issues") is
**substantially true for the CLI / REPL / engine / modal surfaces** —
every documented entry point is wired and tested end-to-end, including
the gate-and-arrow dispatch path, the Tier-2 verdict modal flow, the
bootstrap pipeline, recovery, attestation persistence and verification.
However, **three runner subsystems exist in production code with zero
production callers**: the adversarial cycle (`Adversary.Attack`,
`AdversarialOrchestrator`, `RemediationLoop`), the amendment-commit
flow (`AmendmentCommitter`), and the project-status aggregator
(`CaptureProjectStatus`). The language-binding evaluator
(`BindingEvaluator`) is similarly orphaned: `grid.LanguageBindings` is
read into the bootstrap.GridFile struct but never registered into the
runner.Registry. None of these gaps map to #23/#24/#25/#26; they are
unannounced gaps in the feature surface.

## Findings

### Dangling

None observed. Every production-callable entry point either succeeds
or fails with a typed error; no path crashes silently or writes
nowhere useful.

### Wired-but-untested

1. **`ghyll memory sync` (cmdMemorySyncManual)** — only the dispatch
   path is unit-tested. The actual sync goroutine `memory.SyncLoop`
   is tested in `memory/syncloop_test.go`, but the CLI subcommand
   that calls `syncer.Fetch` + `syncer.CommitAndPush` from a manual
   trigger has no `cmd/ghyll/memory_cmd_test.go` coverage. Requires a
   real git repo, so a runtime fixture is needed.

2. **`cmd/ghyll-vault/main.go`** — no `_test.go` file in
   `cmd/ghyll-vault/`. The `vault/` package itself has
   `server_test.go`, `server_security_test.go`, `v2_endpoints_test.go`,
   `v2_helpers_coverage_test.go`. The CLI entry point (which loads
   config, opens the sqlite store, starts the HTTP listener) is
   uncovered. Coupled with #26: the entry point also has a hardcoded
   `:9090` and no `--config` flag, so the integration surface has
   neither tests nor flag coverage.

3. **`Session.vaultClient` (memory.VaultClient)** —
   `cmd/ghyll/main.go:290` constructs it, `session.go:165` stores it
   on the Session struct, but **no production caller in cmd/ghyll
   reads `s.vaultClient`**. The vault Search/Push paths only have
   acceptance-test callers (steps_vault.go). Either the session never
   needed to talk to the vault, or the wiring was started and never
   completed. Not a crash hazard (nil-safe by default), but the
   field is dead weight.

### Aspirational

These are production-package types and functions with **zero production
callers anywhere in `cmd/`**, only test references. After "prod-
readiness", these should not exist or should be moved to test helpers /
internal harness packages.

1. **`runner.AdversarialOrchestrator`** (orchestrator.go) — the bounded
   multi-round adversarial driver. Referenced only in
   `orchestrator_test.go`, `producer_fix_test.go`,
   `tests/acceptance/steps_adversarial_*.go`. The runtime dispatcher
   (`runner/dispatcher.go:Dispatch`) does not invoke any adversarial
   phase after the clauses evaluate — it derives the arrow status and
   returns. **The runtime never runs an adversarial pass against a
   real arrow.**

2. **`runner.RemediationLoop`** (remediation.go) — bounded multi-round
   adversary→fix loop. Referenced only in `remediation_test.go` and
   acceptance steps. Same root cause as #1 above.

3. **`runner.Adversary` + `Adversary.Attack`** (adversarial.go) —
   single-shot adversary coordinator. Only `adversarial_test.go` and
   the orphan `RemediationLoop` call it. No production caller.

4. **`runner.AmendmentCommitter`** (amendment_commit.go) — the typed
   commit driver for drained AmendmentRequests. Referenced only in
   acceptance steps (pass-lifecycle, amendment-deferred,
   amendment-lock-recovery, runner-deferred). The session loop
   constructs the AmendmentQueue (session_engine.go:156) and the
   journal observer persists writes to it, but **no production code
   path commits queued amendments into the grid via
   `AmendmentCommitter.Commit`**. The runtime accepts amendments into
   the queue but never drains them into the grid in production.

5. **`runner.CaptureProjectStatus`** (projectstatus.go) — the project-
   level snapshot aggregator. Defined in production, called nowhere.
   The `/status` slash-command builds its own minimal output inline
   (session.go:1347). The full project-status aggregator is dead.

6. **`runner.BindingEvaluator` + language-binding registration**
   (subprocess.go) — `bootstrap.GridFile.LanguageBindings` is parsed
   into a Go map (bootstrap/grid.go:28) but **no production caller
   reads that map and registers per-language evaluators against the
   runner.Registry**. `RegisterBuiltins` (notodo.go:402) only
   registers 7 universal evaluators (no-todo-marker, trace-link-
   present, arrow-artifact-present, cardinality-check,
   no-open-finding, kill-server-fails-integration, every-requirement-
   meets-min-depth). Concepts like `compiles`, `lint-clean`,
   `tests-pass`, `mutation-score` declared on arrows would crash with
   `ErrConceptNotRegistered` in production because the binding
   pipeline never runs. Acceptance tests construct `BindingEvaluator`
   directly via `runner.NewBindingEvaluator`.

7. **`bootstrap.Session` + `bootstrap.SessionRegistry`** (session.go)
   — the operator-session single-active enforcement. Defined in
   production, referenced only in acceptance steps
   (steps_session_registry.go, steps_attestation.go,
   steps_attestation_modal.go). `cmd/ghyll/init_bootstrap_cmd.go`
   does NOT use the SessionRegistry — it runs the non-interactive
   auto-accept path. The `/op-id` REPL handler also doesn't use the
   registry; it just stores `opID` on Session. The "single active
   operator across processes / sessions" invariant has no runtime
   enforcement.

8. **`bootstrap.CheckModification`** (modify.go) — directional modify
   rules for path-glob + regex narrowing. Defined in production,
   called only from acceptance steps_init.go and
   steps_modify_non_monotonic.go. No production caller in
   `cmd/ghyll/init_*.go` exercises the modify-on-unknown-clause path
   either; `autoAcceptProposal` only does Confirm or Skip, never
   Modify.

9. **`bootstrap.ExtractContextSymbols` + `ClassifyOrphans`**
   (orphan.go) — orphan-symbol extraction (Go extractor). Defined in
   production, called only from acceptance steps_orphan.go. The
   bootstrap pipeline in `cmd/ghyll/init_bootstrap_cmd.go` does not
   walk source code for orphan extraction.

10. **`bootstrap.RiskAssessment` + `ProposeRefusal` / `AcceptRefusal`
    / `OverrideRefusal`** (risk.go + profile.go) — risk-based
    refusal flow. Defined in production, called only from acceptance
    steps_refusal.go. The `init` CLI never calls `ProposeRefusal`.

## Verdict

**Yes-with-7-aspirational-subsystems.**

The product is feature-complete for the CLI / REPL / engine / modal /
bootstrap / recovery / memory-sync / dialect-routing surfaces. Every
documented entry point is wired and tested end-to-end; build (`go
build ./...`), vet (`go vet ./...`), and unit tests (`go test -short
./cmd/ghyll/... ./bootstrap/... ./runner/... ./engine/... ./dialect/`)
are all clean.

The user's claim is **wrong** on three substantive points that fall
outside #23/#24/#25/#26:

1. **No adversarial cycle runs in production.** The dispatcher
   evaluates clauses and returns; it never invokes
   `Adversary.Attack`, `RemediationLoop`, or `AdversarialOrchestrator`.
   These exist in `runner/` with zero production callers. `gates.md
   §11` says "every arrow runs an adversarial phase" — the code does
   not implement that.

2. **No amendment drain runs in production.** The
   `AmendmentCommitter` that turns drained `AmendmentRequest`s into
   actual grid mutations is test-only. Amendments accumulate in the
   queue but are never applied to the live grid by any production
   code path.

3. **No language-binding evaluation runs in production.** The grid's
   `language-bindings` map is parsed but never registered against
   the runner registry. Any arrow that declares a `compiles` or
   `tests-pass` or `lint-clean` clause crashes at evaluation with
   `ErrConceptNotRegistered`. Only the 7 universal-base evaluators
   work end-to-end.

Plus four smaller aspirational gaps (Session/Registry, modify rules,
orphan extraction, risk-based refusal) and three wired-but-untested
items (cmdMemorySyncManual, cmd/ghyll-vault, dead
Session.vaultClient).
