# Doc audit findings — 2026-05-25

## Summary

Top-level prose (README.md, why.md, operator-guide.md) is in good
shape after the recent rewrite and accurately reflects the
post-prod-readiness state of the runtime. The pre-existing reference
material under `docs/architecture/` and `docs/internals/` and the
older `docs/usage/cli-reference.md` / `docs/usage/troubleshooting.md`
have NOT been refreshed in line with the v2 gate-and-arrow surface:
they still describe v1 packages, omit every v2 CLI subcommand
(`init`, `init attest`, `engine *`, `arrow show`), and contradict
the new top-level prose on filenames, defaults, and behaviors. The
single most novice-hostile gap is that **neither the README nor
getting-started.md ever gives a worked, end-to-end example of what
the operator sees from `ghyll init` to a recorded verdict** — every
"arrow"/"pass"/"op-id"/"clause" definition is given in jargon
without a screenshot-style walkthrough.

No showstoppers — no doc tells a user to run a command that crashes
— but `docs/usage/troubleshooting.md` and `docs/usage/cli-reference.md`
are stale enough that a novice following them will hit confusing
error messages instead of the actual ones.

## Recommended next moves

1. **Refresh `docs/usage/cli-reference.md` and `docs/usage/troubleshooting.md` first** — they're the worst stale, document non-existent error messages and miss every v2 subcommand. A novice following the cli-reference will conclude `ghyll init` doesn't exist, and a novice hitting first-run will get an unfamiliar "wrote default config" message that troubleshooting.md can't help them parse.
