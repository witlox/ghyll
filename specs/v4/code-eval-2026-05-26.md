# Code integrator pass #2 — 2026-05-26
## (since prior eval at e23ba55, excludes GH issues #23-#38)

## Summary

Diamond v4 wiring has substantively closed the three big aspirational
gaps from the 2026-05-25 pass — `RunRemediationLoop`, `Adversary.Attack`,
`AmendmentCommitter.Commit`, and per-grid `BindingEvaluator`
registration are all reachable from production CLI paths
(`/run-arrow`, `/drain-amendments`, depth-sensitive dispatch). The
new seed-on-empty + `--language` trait-block substrate works in
isolation but is not threaded through every plausible operator flow.
The most consequential newly-introduced gap is `OpEventArrowInvalidated`:
the producer (`/invalidate-arrow`) and SQLite persistence are wired,
but there is no read consumer — `/list-arrows`, `ghyll arrow show`,
`/run-arrow`, the JSONL audit, and engine.Replay all ignore the
table, so invalidated arrows are invisible to operators and the
dispatcher will still run them.

Build, vet, unit tests, and `make coverage-check` (78.4%) are clean.

## Verdict

**Anything not in GH issues yet? Yes — three items, plus a handful of low-severity polish gaps.**

- Total findings outside #23-#38: **11** (3 Dangling, 5 Wired-but-untested, 7 Newly-introduced; some overlap by theme).
- The three that warrant new GH issues:
  1. **arrow_invalidations is write-only audit with no enforcement** (D-1 + N-1 together): the operator's `/invalidate-arrow` writes a row and emits a banner, but `/run-arrow` still dispatches the invalidated arrow, `/list-arrows` doesn't surface invalidation, and Replay/Recovery don't load the table. The producer + persistence are wired; the read consumer is missing.
  2. **`--language auto` with empty profile.Languages silently skips the trait block** (W-2 + N-2): operators running `ghyll init` on a polyglot or unrecognized-language repo get no engineering.md in their project instructions and no warning that the language library was bypassed.
  3. **`~/.ghyll/` dir mode is left at whatever the operator's pre-existing mode was** (D-3): both `ensureConfig` and `seedUserHome` use `MkdirAll(0o700)`, which is a no-op when the dir already exists. The `bootstrap.Grid.Write` path Chmod-fixes the project `.ghyll/`; the user-home seed and config bootstrap should match.

The user's product is **substantively feature-complete** for everything
declared by the diamond-v4 ADRs; the gaps above are correctness +
operator-visibility seams the v4 commits opened or left open, not
unfinished v4 scope.
